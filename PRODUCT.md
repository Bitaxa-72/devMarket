# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

- Клиенты Devmarket регистрируются, оплачивают и отслеживают цифровые проекты, документы и переписку.
- Менеджеры сопровождают проекты и общаются с клиентами.
- Главный администратор управляет пользователями, заказами, платежами и доступами.

## Product Purpose

Devmarket объединяет каталог готовых цифровых решений, заказ разработки и личный кабинет для совместной работы над проектами.

## Operating Context

Пользователь может прийти из каталога или оформления заказа, создать аккаунт, подтвердить email, войти и продолжить работу в личном кабинете. Восстановление доступа выполняется по одноразовой ссылке из письма.

## Capabilities and Constraints

- Frontend: React и Vite.
- Backend: NestJS, PostgreSQL и Drizzle ORM, API с префиксом `/api/v1`.
- Роли backend: `customer`, `manager`, `admin`.
- Аутентификация использует серверные сессии в защищённых cookie, а не токены в localStorage.
- Регистрация требует подтверждения email.
- Ответ восстановления пароля не раскрывает наличие аккаунта.
- Пользователь может придумать пароль самостоятельно или сгенерировать надёжный пароль в браузере.
- Публичный сайт и личный кабинет остаются частями одного продукта, но кабинет получает собственный рабочий интерфейс.

## Brand Commitments

Название продукта — Devmarket. Основной акцентный цвет — фирменный зелёный, общий визуальный язык сохраняет сдержанную деловую подачу существующего сайта.

## Evidence on Hand

- Каталог, корзина, оплата и прототип личного кабинета находятся в `src`.
- Backend-схема пользователей и сессий находится в `../backend/src/modules/database/schema/identity.ts`.
- Реальные SMTP-реквизиты и персональные данные не должны добавляться в репозиторий.

## Product Principles

- Не раскрывать существование аккаунта незарегистрированному посетителю.
- Делать восстановление доступа понятным без ослабления безопасности.
- Показывать следующий шаг после каждого действия.
- Не хранить секреты аутентификации в браузерном хранилище.
- Разделять возможности пользователей по ролям на стороне сервера.

## Accessibility & Inclusion

Формы должны работать с клавиатуры, иметь явные подписи, читаемые ошибки, видимый фокус и сообщения состояния для вспомогательных технологий.
